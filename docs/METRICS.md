# Метрики (честные, на своём тест-сете)

## Точность измерения крена кузова (контролируемый тест)
Берём чистые реальные фото фур (Wikimedia Commons, свободные лицензии), которые
детектируются как truck и читаются с креном ~0°. Поворачиваем на известные углы
и обрезаем края (валидная синтетическая аугментация, задекларирована) —
ground-truth = заданный угол. Крен считается боевым пайплайном (бокс прицепа
YOLO-World + геометрия кромок). 14 базовых фото × 8 углов = 83 замера.

- **TILT MAE = 3.70°** (медиана 2.88°).
- По углам: ±3° → ~1.9–2.9°; ±5° → ~2.6–4.7°; ±8° → ~3.0–4.7°; ±12° → ~4.8°.
- Грубый крен (≥10°) уверенно отделяется от нормы; у границ порога (4–7°)
  возможны пограничные ошибки — честно заявлено.

Воспроизвести: `python src/eval_tilt.py data/images/public 40`

## Поведение на ПРОИЗВОЛЬНЫХ фото (честно)
На косых/загромождённых кадрах (перспектива) система не угадывает, а возвращает
**«не оценить» (cannot-assess)** — на выборке из 120 фото доля таких ~44%,
грузовик не найден ~10%. Это by design: лучше честный отказ, чем ложный NO-GO.
Надёжная зона — целевой сценарий: камера на воротах, вид сзади/сбоку, кузов целиком.

## Скорость / стоимость
- Полный пайплайн (YOLOv8n + геометрия) на CPU ноутбука: **~29 мс/кадр ≈ 34 FPS**.
- Инференс полностью CPU, без GPU в проде. При ~$0.01/CPU-час эконом-инстанса и
  34 кадр/с одна проверка ≈ доли копейки; ботлнек — сеть/загрузка фото, а не модель.

## Известные failure-cases (честно)
- Ошибка крена растёт на больших углах (|10°| → ~3.8°).
- Полуприцеп с горизонтальным бортом: измеряется крен кузова, а не кабины.
- Ночь/сильные блики/частичный кадр/нестандартный ракурс — требуют дообучения на своих данных.
- Детекция свеса/крепления/высоты — включается после обучения этих классов (train/).
